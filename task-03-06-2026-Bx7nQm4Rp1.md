# Task: Remover CookieCutter — generate_project.py como gerador único

## Contexto

O AgtecCore possui dois mecanismos de geração de projetos Django:

1. **CookieCutter (legado)** — via `cookiecutter.json` + `hooks/` (pre/post hooks) + dependência `cookiecutter>=2.7.1` no `pyproject.toml`
2. **generate_project.py (novo)** — script Python autônomo com Jinja2, sem dependência de CookieCutter

O script `generate_project.py` já reimplementa toda a lógica dos hooks (scaffold, .env, deps, build apps, git init, format). A demanda é eliminar o CookieCutter completamente, limpando os artefatos legados e garantindo que testes e documentação reflitam o novo fluxo.

## Análise do estado atual

### Artefatos CookieCutter a remover (raiz do AgtecCore)

| Arquivo | Motivo da remoção |
|---|---|
| `cookiecutter.json` | Config do CookieCutter — substituído por `generate_project.py` |
| `hooks/pre_gen_project.py` | Randomizava ports e criava backup do cookiecutter.json — não mais necessário |
| `hooks/post_gen_project.py` | Copiava arquivos, .env, deps, apps, git — tudo reimplementado em `generate_project.py` |
| `hooks/` (dir vazio) | Remover após apagar os hooks |

### Arquivos que referenciam CookieCutter e precisam de atualização

| Arquivo | O que mudar |
|---|---|
| `pyproject.toml` | Remover `cookiecutter>=2.7.1` das dependências; corrigir `--cov={{cookiecutter.project_slug.lower()}}` no pytest (literal inválido) |
| `tests/test_generate_project.py` | Remover `TestCookiecutterJson`, `TestLegacyCookiecutterHook` e constantes `COOKIECUTTER_JSON`/`POST_GEN_HOOK` |
| `README.md` | Remover seção "Opção 2 — CookieCutter (legado)" e imagem `cookiecutter.png` |
| `.github/workflows/pages.yml` | Linha 35: `cd {{cookiecutter.project_slug}}` — avaliar se workflow ainda faz sentido e corrigir path |

### Artefatos que NÃO devem ser alterados

- `{{cookiecutter.project_slug}}/` — é o diretório template; os `{{ cookiecutter.* }}` ali dentro são variáveis Jinja2 consumidas pelo `generate_project.py` (o nome do dir é literal intencional)
- `generate_project.py` — já funcional e com testes; não requer mudanças estruturais nesta task

### Comportamento legado que precisa de decisão

O `pre_gen_project.py` randomizava as portas `docker_port` e `postgre_port` a cada execução (para evitar conflitos entre projetos). O `generate_project.py` atual usa defaults fixos (`8000` e `5432`) mas permite sobrescrever via prompt ou `--docker-port`/`--postgre-port`. **Decisão necessária antes de implementar:** adicionar randomização automática como os antigos hooks faziam, ou manter comportamento atual (prompt com default fixo)?
